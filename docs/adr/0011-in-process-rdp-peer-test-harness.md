# ADR-0011: Test against real in-process FreeRDP server peers over socket pairs, with no network, credentials or Keychain

## Status

Accepted (retrospective, inferred 2026-10-29)

## Context

Testing an RDP client normally needs real Windows hosts and accounts, which cannot be in a repo or CI.

## Decision

`Tests/Tests.m` builds FreeRDP server peers (`freerdp_peer`) that run over `socketpair` with throwaway self-signed certificates generated by `scripts/test.sh` (openssl@3 from Homebrew) under ignored `build/test-data`. A test subclass overrides the `prepareTransport:` seam in `QDSession.m` to replace FreeRDP's TCP connect with the socket pair; the shipped app always uses normal TCP. Tests run four simultaneous TLS handshakes, check decoded pixel colours, input isolation, disconnect/reconnect, certificate reject/connect-once/trust/changed, and cancellation; plus profile persistence, validation, permissions, corrupt-file handling, key mapping, letterbox maths and image creation. `QUADRDP_DATA_DIR` isolates test data; tests create no Keychain items. Results are filtered with `rg` in `scripts/test.sh`.

## Consequences

### Positive

- Real protocol coverage with no secrets or open ports; safe to run anywhere the dependencies exist.

### Negative

- NLA (CredSSP) and the Keychain prompt flow are not exercised; README says they still need end-to-end checking against real hosts.
- `scripts/test.sh` also needs ripgrep (`rg`) and Homebrew `openssl@3`, which the README's install line does not mention (A-007).
- No CI workflow exists in the repo, so tests only run when invoked by hand.

## Alternatives considered

The repository has a single commit and no design notes, so alternatives below are only those the code or README names; anything else is marked as not evidenced.

- Mocking FreeRDP entirely: not used; the harness drives the real library.
